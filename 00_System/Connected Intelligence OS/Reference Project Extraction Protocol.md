# Reference Project Extraction Protocol

Purpose: turn a real repository into bounded experience without copying project-specific accidents into future systems.

## Trigger
Use when Omar says a project should enter the Brain so future projects can learn from it.

## Mandatory sequence
1. **Resolve identity** — exact `project_id`, repo, default branch and revision.
2. **Lock evidence scope** — state whether inspection is repo-only, runtime, deployment or mixed.
3. **Inspect reality** — package/build files, architecture docs, schema, security boundaries, critical flows, tests, operations and recent history.
4. **Create repo-grounded run** — record the assessment as real work.
5. **Create evidence records** — exact commit, files, hashes/refs and limits.
6. **Build project packet** — context, architecture, strengths, risks, future path, current state, queue, repo map, evidence matrix and scorecard.
7. **Extract transfer candidates** — each candidate needs claim, applicability and boundary.
8. **Extract anti-transfer warnings** — project-specific or weak behavior future projects must not inherit.
9. **Compile experience** — candidates remain proposed after one project.
10. **Promote only after independent validation** — another project must provide real evidence.

## Required packet
```text
00_PROJECT_HOME.md
01_CONTEXT.md
02_ARCHITECTURE.md
03_GOOD_POINTS.md

05_FUTURE_PATH.md

07_CURRENT_STATE.md
08_EXECUTION_QUEUE.md
09_REPO_MAP.md
10_EVIDENCE_MATRIX.md
11_REFERENCE_SCORECARD.md
```

## Truth rules
- Repository evidence proves repository state, not runtime success.
- Documentation is evidence of intended architecture; selected code must be cross-checked for load-bearing claims.
- Missing proof becomes a verification gap, not a fabricated defect.
- One project can propose a reusable pattern; it cannot validate a universal pattern.
- A high reference value does not imply high production readiness.

## Transfer decision
For each future project ask:
```text
Is the same problem present?
Is the same risk level present?
Are the same constraints present?
What evidence supports applicability?
What must be adapted?
What must not be copied?
```
