# Connected Intelligence Operating System

## Mission
Make Omar Brain improve through real work rather than document count. The system must preserve identity, causality, provenance, authority, project context and learning state across every durable write.

## Core loop
```text
real work -> run -> result -> evidence -> causal links -> project truth update
         -> experience compiler -> learning candidate -> validation -> reusable memory
         -> better future retrieval -> better action -> new evidence
```

## Non-negotiable laws
1. No durable information without a stable object identity or an explicit inbox state.
2. No silent overwrite. Conflicts stay explicit until resolved by authority and evidence.
3. No claim becomes verified because an AI wrote it.
4. No reusable lesson is promoted from one project success alone.
5. Every event keeps correlation context; causal links are never guessed.
6. Every AI context item must have a reason for inclusion.
7. Project truth outranks general memory for current project execution.
8. Real repository/runtime evidence outranks remembered conversation context.
9. The fewest agents and fewest context objects necessary should be loaded.
10. Health must fall when reality coverage is missing; empty experience can never score 100.

## Control plane
- `object-registry.json` — stable identity and canonical location.
- `edge-ledger.jsonl` — typed relationships only.
- `event-ledger.jsonl` — append-only operational nervous system.
- `provenance-ledger.jsonl` — source and derivation trace.
- `transaction-ledger.jsonl` — committed/rejected brain mutations.
- `impact-queue.json` — objects requiring revalidation or synchronization.
- `learning-candidates.json` — proposed reusable experience; never automatic truth.
- `reality-coverage.json` — honest experience coverage.

## Write path
```text
input -> identity resolution -> project/entity resolution -> authority check
      -> dedupe -> contradiction scan -> staged transaction -> validation
      -> canonical write -> typed edges -> provenance -> durable event
      -> impact propagation -> experience review -> affected reindex/eval
```

## Read path
```text
request -> intent -> project -> authority/freshness need -> route -> primary skill
        -> graph expansion -> evidence selection -> compact context pack
        -> each item carries why_included
```

## Start rule for AI
Read [[00_System/Operating Map]], then resolve through this OS before writing durable information or resuming a real project.

## Repo-grounded reference projects
When Omar designates a real project as a learning source, follow [[Reference Project Extraction Protocol]] so strengths, risks and transfer candidates remain evidence-bounded.
