# Impact Propagation Policy

New information is useful only when affected truth is discovered and reviewed.

## Impact states
`pending`, `reviewing`, `resolved`, `dismissed`.

## Trigger examples
- Project claim changes -> review current state, requirements, queue and relevant decisions.
- External API behavior changes -> review projects, assumptions, integration skills and production checks.
- Failure signature repeats -> review prior resolution and applicability boundary.
- Canonical decision superseded -> revalidate dependents.

## Rule
Impact analysis proposes affected objects; it does not silently rewrite them.
