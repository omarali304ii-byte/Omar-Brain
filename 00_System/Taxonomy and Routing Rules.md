# Taxonomy and Routing Rules

Classify by purpose, not keywords.

## Deterministic routing tree

1. Raw, ambiguous, unprocessed? → `01_Inbox`
2. Durable possibility not yet committed to a finite outcome? → `15_Ideas`
3. Time-bounded outcome with a done definition? → `40_Projects`
4. Ongoing personal responsibility/system? → `10_Life`
5. Professional identity, role, opportunity, CV, portfolio? → `20_Career`
6. Business entity/product/client/operation/strategy? → `30_Business`
7. Capability Omar deliberately improves? → `50_Skills`
8. Reusable understanding, pattern, failure, lesson, playbook, source? → `60_Knowledge`
9. Primarily a person/relationship context? → `70_People`
10. Time-based reflection/review? → `80_Reviews`
11. Inactive durable material? → `90_Archive`
12. Binary/raw non-note asset? → `99_Assets`

## Project trigger
If content names or implies an existing project and asks for implementation, debugging, planning, or state, resolve the canonical project before acting. Do not create a new project merely because a new feature idea appears.

## Idea vs project
- “Maybe build X” → idea.
- “Build X with outcome Y and done when Z” → project.
- A project-scoped idea stays linked to the project and may live in project Working/Research until promoted.

## Knowledge extraction
Project material becomes global knowledge only when reuse is plausible and evidence is preserved.

## Uncertainty
If primary type remains uncertain after search, route to Inbox with candidate routes and source preserved.
