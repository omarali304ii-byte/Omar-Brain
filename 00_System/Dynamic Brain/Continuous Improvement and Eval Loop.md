# Continuous Improvement and Eval Loop

## Loop
1. capture real run outcome,
2. detect failure/user correction/strong success,
3. create or update eval case,
4. create memory/capability proposal if reusable,
5. test change offline,
6. compare baseline,
7. approve/reject,
8. deploy change,
9. monitor real outcomes,
10. rollback if regression.

## What can improve
- retrieval chunking,
- metadata filters,
- routing,
- capability selection,
- prompts/skills,
- tool contracts,
- architecture standards.

## What cannot self-change without governance
- Brain Constitution,
- high-risk approval policy,
- privacy boundaries,
- durable memory writer rule,
- destructive tool permissions.

## Anti-metric
More notes, more agents, and more tokens are not evidence of improvement.
