# AI Change Policy

## Low-risk changes AI may make when authorized
- normalize controlled metadata,
- add missing obvious links,
- route inbox items with high confidence,
- update current-state sections from verified evidence,
- update execution queue after real work,
- append run records,
- create failure signatures from observed failures,
- create candidate lessons linked to evidence,
- create a project/skill/idea from explicit instruction using approved scaffold/template.

## Medium-risk changes requiring a clear report and verification
- merge notes,
- move durable notes,
- split a large note,
- change active project status,
- revise current architecture summary,
- mark a lesson validated,
- supersede durable knowledge,
- repair documentation drift.

## High-risk changes requiring explicit approval or approved governance flow
- delete durable notes,
- transmit restricted material externally,
- change `ai_access` from denied/restricted to allowed,
- rewrite personal history,
- mark project complete without direct Done evidence,
- change Constitution/taxonomy/schema,
- change architecture profiles or security standards,
- change stop conditions,
- promote a pattern to a global standard,
- lower evidence/promotion thresholds.

## Self-improvement rule
AI may generate `change-proposal` notes and candidate patterns. It may not approve its own global law changes.

## Destructive confidence rule
When uncertain, preserve evidence, surface ambiguity, and continue safe independent work. Organization is never an excuse for destructive guessing.
