# Create PRD

## Purpose

Create an authoritative PRD that aligns problem, objective, segment, value, solution, assumptions, success metrics, and release scope.

## When to activate

- create prd
- product requirements document
- feature spec
- requirements document
- product spec

## Inputs required

- Problem evidence
- Target segment
- Business objective
- Constraints
- Research and assumptions
- Existing product context

## Workflow

1. Gather and separate known facts from assumptions.
2. Define problem/background and why now.
3. Define measurable objective and success metrics.
4. Define target segment by problem/JTBD, not demographics alone.
5. Articulate segment-specific value proposition.
6. Specify solution, UX, key features, technology constraints, and assumptions.
7. Define first release vs later scope and explicit non-goals.
8. Link acceptance criteria and validation needs.

## Outputs

- Structured PRD
- Assumption register
- Success metrics
- Release scope/non-goals
- Open questions

## Quality gates

- [ ] No feature list without problem/objective
- [ ] Assumptions clearly labeled
- [ ] Success metrics measurable
- [ ] Release scope and non-goals explicit

## Road signs

- When **implementation context** dominates → go to **Context Engineering**.
- When **QA** dominates → go to **Test Scenarios**.
- When **strategy uncertainty** dominates → go to **Product Strategy**.
